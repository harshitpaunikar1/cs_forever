# Costs and Cost Minimization (Opportunity Cost, Sunk Cost, Isocosts, Input Demand)


## Overview

Cost is not just money spent; it includes what you give up. Cost minimization means producing a target output at the lowest cost using the best input mix.


## Why It Matters

It improves profit and helps avoid bad decisions like “we already spent money, so continue” (sunk cost trap).


## Key Principles

- Economic cost includes opportunity cost.
- Ignore sunk costs for forward decisions.
- Long-run: all inputs adjustable. Short-run: some fixed.
- Optimal input mix is where isoquant meets the lowest isocost.


## Key Terms

| Term | Definition |
|------|------------|
| **Opportunity Cost** | Best alternative given up. |
| **Sunk Cost** | Past cost that can’t be recovered. |
| **Isocost Line** | Same total cost combinations of inputs. |
| **Input Demand** | Cost-minimizing amount of each input. |


## Use Case

Choosing between outsourcing and in-house production.


## Scenario

> A firm already bought an old machine (sunk cost). A new supplier offers cheaper production now. The firm compares future costs, not past spending.


## Examples

- Sunk cost: paid for a lease—don’t keep a bad store just because of that.
- Opportunity cost: using founder’s time in operations means less time on growth.

## 1. Topic Snapshot
This topic is about producing a target output at the lowest real cost, not the lowest accounting invoice.  
For IT/AI/Product/Consulting leaders, the decision is whether to outsource, buy more input, change the input mix, or stop a project that only feels expensive because money was already spent.  
The practical goal is to avoid sunk-cost traps and choose the cheapest feasible input combination for the required output.

## 3. Frameworks & Matrices
The frameworks below turn the chapter into usable operating logic [verified from model knowledge, not source].

### Forward-Looking Cost Test
**Purpose:** Decide whether a cost should matter in the current decision.

**Text Diagram:**
```text
past spend -> ignore if sunk
future spend -> include in decision
foregone alternative -> include as opportunity cost
```

Axes / Quadrants / Components explained:
Component 1: sunk versus future - whether the cost can still be changed.
Component 2: explicit versus hidden - whether the cost is visible on an invoice or only in what is sacrificed.
Component 3: decision relevance - whether the cost changes the next action.
Component 4: reversibility - whether the choice can be undone cheaply.

IT/AI/Product/Consulting worked example: A team already spent on an old vendor contract. The contract is sunk; the real question is whether continuing with it is more expensive than switching now.

When to pull this out in a meeting: When someone says "we already paid for it, so we should keep going."

### Isoquant-Isocost Optimization Map
**Purpose:** Find the cheapest input mix for a required output.

**Text Diagram:**
```text
output target on isoquant
lowest touching isocost = optimal mix
```

Axes / Quadrants / Components explained:
Component 1: isoquant - all input mixes that achieve the same output.
Component 2: isocost - all input mixes that cost the same.
Component 3: slope tradeoff - how one input substitutes for another.
Component 4: optimum - where the target isoquant touches the lowest possible isocost.

IT/AI/Product/Consulting worked example: A product team can run inference on more cloud compute or refactor code to use less compute. The map shows which mix hits the same output at lower cost.

When to pull this out in a meeting: When the team needs the same outcome but wants to know the cheapest way to get it.

### Make-or-Buy Decision Matrix
**Purpose:** Compare outsourcing with in-house production.

**Text Diagram:**
```text
high internal capability / low risk -> make in-house
low internal capability / high flexibility need -> buy or outsource
high quality risk -> hybrid or dual-source
high strategic value -> keep control in-house
```

Axes / Quadrants / Components explained:
Component 1: cost - direct and opportunity cost.
Component 2: control - quality, speed, and IP protection.
Component 3: flexibility - ability to scale up or down.
Component 4: strategic value - whether the capability is core to the business.

IT/AI/Product/Consulting worked example: A consulting firm can either build an internal analytics tool or buy one. If the tool is core to client delivery and data sensitivity is high, in-house may be worth the extra cost.

When to pull this out in a meeting: When procurement, finance, and product disagree on outsourcing.

## 4. Formulas
The source does not define formulas, so the metrics below are practical operating proxies [verified from model knowledge, not source].

### Formula 1: Economic Cost
Formula: `Economic Cost = explicit cost + opportunity cost`
Variables:
explicit cost = money actually paid
opportunity cost = value of the next-best alternative forgone
Why this formula exists: It answers the real cost of a choice, not just the accounting cost.
How to interpret the output:
Value close to explicit cost -> few hidden tradeoffs
Value materially above explicit cost -> the decision is more expensive than it looks
Value far above explicit cost -> reconsider the plan
Worked example with numbers: If a founder spends 80k in cash and gives up 20k of alternative consulting income, economic cost is 100k. Decision: compare the project against the full 100k, not just the cash.

### Formula 2: Total Cost
Formula: `Total Cost = fixed cost + variable cost`
Variables:
fixed cost = cost that does not change with output in the short run
variable cost = cost that changes with output
Why this formula exists: It answers what the operation really spends at a given scale.
How to interpret the output:
Low fixed share -> flexible but potentially unstable
Balanced share -> many standard operations
High fixed share -> scale matters a lot
Worked example with numbers: If cloud reserved capacity is 200k and variable usage is 150k, total cost is 350k. Decision: if demand is volatile, check whether fixed commitment is too high.

### Formula 3: Isocost Line
Formula: `C = wL + rK`
Variables:
C = total cost
w = price of labor
L = labor quantity
r = price of capital
K = capital quantity
Why this formula exists: It answers which labor-capital combinations fit the budget.
How to interpret the output:
Lower C -> cheaper feasible combinations
Higher w or r -> the budget line gets tighter
Changing L or K -> substitution between inputs
Worked example with numbers: If labor costs 50 per unit, capital costs 100 per unit, and the budget is 1,000, then 10 units of labor and 5 units of capital are feasible. Decision: adjust the mix until the output target is met at the lowest cost.

### Formula 4: Cost-Minimizing Condition
Formula: `MRTS = w / r`
Variables:
MRTS = marginal rate of technical substitution
w = price of labor
r = price of capital
Why this formula exists: It answers when the input mix is optimally balanced.
How to interpret the output:
MRTS > w/r -> use more of the cheaper input
MRTS = w/r -> cost-minimizing mix reached
MRTS < w/r -> use more of the other input
Worked example with numbers: If labor can substitute for capital at 2 units of capital per 1 unit of labor, but w/r is only 1, labor is relatively cheap. Decision: shift toward labor until the ratio equalizes.

## 5. Do vs Don't
| ❌ Don't | ✅ Do |
|---------|-------|
| Keep a bad project only because money was already spent. | Treat sunk cost as irrelevant and decide on future value. |
| Choose inputs by habit. | Find the lowest cost input mix for the output target. |
| Assume the cheapest invoice is the cheapest decision. | Include opportunity cost, quality risk, and adjustment time. |
| Outsource core capability without a control check. | Compare cost, flexibility, and strategic value before buying or making. |
| Hold fixed capacity forever just because it is already there. | Re-evaluate fixed inputs as demand and technology change. |

## 6. Real-Life Scenarios (Metric-Driven)
### Scenario 1: Old vendor contract versus switching
Situation: A product team has already paid for an old analytics vendor, but a cheaper supplier now offers better performance. Leadership wants to avoid "wasting" the old spend.
Applicable framework/metric: Forward-Looking Cost Test and Economic Cost.
Analysis: If the old contract is sunk and the new supplier reduces future cost by 30k, the switch should be evaluated on future savings, not past payment. [verified from model knowledge, not source]
Decision rule: If future savings exceed switching cost, move. If savings are marginal, renegotiate. If the old contract still has strategic value, keep it only for that reason.
Action: Compare future run-rate, migration cost, and quality impact before renewing.

### Scenario 2: Build versus buy for an AI capability
Situation: An AI team can either buy a model monitoring tool or build one in-house. Security, speed, and product control all matter.
Applicable framework/metric: Make-or-Buy Decision Matrix and Total Cost.
Analysis: If internal build cost is 400k upfront with low variable cost, but vendor cost is 120k annually with lower control, the right choice depends on time horizon and strategic importance. [verified from model knowledge, not source]
Decision rule: If the capability is core and sensitive, lean in-house. If it is non-core and easy to replace, outsource. If both options are viable, run a pilot and compare total cost.
Action: Score control, flexibility, and data sensitivity before deciding.

### Scenario 3: Cloud compute versus code optimization
Situation: A product engineering team needs more inference throughput for a launch. One option is to buy more cloud compute; the other is to refactor the code.
Applicable framework/metric: Isoquant-Isocost Optimization Map and Cost-Minimizing Condition.
Analysis: If compute is expensive and the current code can reduce load by 20% with a one-time refactor, the cheaper path may be engineering work instead of brute-force scaling. [verified from model knowledge, not source]
Decision rule: If the cheaper input is substitutable without harming output, switch. If substitution harms quality, keep the expensive input and redesign later.
Action: Run a quick cost-per-output comparison, then choose the lower-cost mix that still meets service levels.

## 7. Implementation Playbook
1. List all relevant inputs, including labor, capital, cloud resources, vendor services, and management time.
2. Separate sunk costs from future costs before making the decision memo.
3. Build a simple isocost sheet showing which input mixes are affordable at the target output.
4. Compare make-versus-buy on cost, control, flexibility, and strategic importance.
5. Test the cheapest feasible input mix on a small run before scaling the decision.
6. Revisit the mix in both short-run and long-run contexts so fixed-input assumptions do not linger too long.
7. Document the opportunity cost that was traded off, not just the invoice total.
