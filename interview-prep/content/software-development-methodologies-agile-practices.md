# Software Development Methodologies & Agile Practices

Interview question bank from `LLM_Azure_AI_Interview_700_QA.docx`.

## Questions

### 1. What is SDLC?

**Answer:** Software Development Life Cycle is the process of planning, building, testing, deploying, and maintaining software.

### 2. What are common SDLC phases?

**Answer:** Requirement gathering, design, development, testing, deployment, and maintenance.

### 3. What is Agile?

**Answer:** Agile is an iterative way of building software with frequent feedback and small releases.

### 4. Why use Agile?

**Answer:** It handles changing requirements betterand delivers value faster.

### 5. What is Scrum?

**Answer:** Scrum is an Agile framework using sprints, roles, events, and artifacts.

### 6. What is a sprint?

**Answer:** A sprint is a fixed time period where theteam completes selected work.

### 7. What is sprint planning?

**Answer:** A meeting where the team decides what work to do in the sprint.

### 8. What is daily standup?

**Answer:** A short meeting to share progress,blockers, and plan for the day.

### 9. What is sprint review?

**Answer:** A meeting to demo completed work and collect feedback.

### 10. What is sprint retrospective?

**Answer:** A meeting to discuss what went well, what did not, and how to improve.

### 11. What is product backlog?

**Answer:** A prioritized list of features, bugs,improvements, and technical tasks.

### 12. What is sprint backlog?

**Answer:** The selected backlog items the team commits to during a sprint.

### 13. What is user story?

**Answer:** A simple requirement written from theuser's perspective.

### 14. What is acceptance criteria?

**Answer:** Clear conditions that define when a user story is complete.

### 15. What is Definition of Done?

**Answer:** A team's checklist for considering work truly finished.

### 16. What is Definition of Ready?

**Answer:** Criteria that a story must meet before itcan enter a sprint.

### 17. What is story point?

**Answer:** A relative estimate of effort, complexity, and uncertainty.

### 18. What is velocity?

**Answer:** The amount of work a team completes in asprint, often measured in story points.

### 19. What is burndown chart?

**Answer:** A chart showing remaining work over time in a sprint.

### 20. What is backlog refinement?

**Answer:** Regularly reviewing, clarifying, splitting, and estimating backlog items.

### 21. Who is Product Owner?

**Answer:** The person responsible for backlog priorityand product value.

### 22. Who is Scrum Master?

**Answer:** The person who helps the team follow Scrum and remove blockers.

### 23. Who is development team?

**Answer:** The people who design, build, test, anddeliver the product increment.

### 24. What is Kanban?

**Answer:** Kanban manages work visually with columns and work-in-progress limits.

### 25. Scrum vs Kanban?

**Answer:** Scrum uses time-boxed sprints; Kanban focuses on continuous flow.

### 26. What is WIP limit?

**Answer:** A limit on how many tasks can be inprogress at once.

### 27. Why use WIP limits?

**Answer:** They reduce multitasking and improve flow.

### 28. What is waterfall model?

**Answer:** A sequential development approach where each phase completes before the nextstarts.

### 29. Agile vs waterfall?

**Answer:** Agile is iterative and flexible; waterfall is sequential and plan-heavy.

### 30. What is DevOps?

**Answer:** DevOps combines development and operations to deliver software faster and more reliably.

### 31. What is CI?

**Answer:** Continuous Integration means frequentlymerging code and automatically testing it.

### 32. What is CD?

**Answer:** Continuous Delivery/Deployment means automating release preparation or production deployment.

### 33. What is version control?

**Answer:** A system like Git that tracks code changes over time.

### 34. What is Git branch?

**Answer:** A separate line of code changes used forfeatures, fixes, or releases.

### 35. What is pull request?

**Answer:** A request to merge code after review and checks.

### 36. Why code review?

**Answer:** It improves quality, catches bugs, sharesknowledge, and enforces standards.

### 37. What is technical debt?

**Answer:** Future cost caused by quick or poor technical decisions.

### 38. How manage technical debt?

**Answer:** Track it, prioritize high-risk debt, refactor regularly, and avoid unnecessaryshortcuts.

### 39. What is refactoring?

**Answer:** Improving code structure without changing external behavior.

### 40. What is clean code?

**Answer:** Code that is readable, simple, well-named,tested, and maintainable.

### 41. What is modular design?

**Answer:** Breaking software into independent parts with clear responsibilities.

### 42. What is separation of concerns?

**Answer:** Keeping different responsibilities indifferent modules/classes/functions.

### 43. What is DRY principle?

**Answer:** Don't Repeat Yourself: avoid duplicated logic.

### 44. What is KISS principle?

**Answer:** Keep It Simple, Stupid: prefer simplesolutions.

### 45. What is YAGNI?

**Answer:** You Aren't Gonna Need It: don't build features before they are needed.

### 46. What is SOLID?

**Answer:** Five object-oriented design principles for maintainable software.

### 47. What is unit testing?

**Answer:** Testing one small piece of codeindependently.

### 48. What is integration testing?

**Answer:** Testing how multiple components work together.

### 49. What is system testing?

**Answer:** Testing the full application as a complete system.

### 50. What is UAT?

**Answer:** User Acceptance Testing checks whetherthe product meets business/user needs.

### 51. What is regression testing?

**Answer:** Testing old functionality after changes to ensure nothing broke.

### 52. What is test automation?

**Answer:** Using scripts/tools to run tests automatically.

### 53. What is TDD?

**Answer:** Test-Driven Development: write tests first, then code to pass them.

### 54. What is BDD?

**Answer:** Behavior-Driven Development usesbusiness-readable scenarios to define behavior.

### 55. What is bug lifecycle?

**Answer:** New, assigned, fixed, tested, reopened orclosed.

### 56. What is severity vs priority?

**Answer:** Severity is impact; priority is urgency/order of fixing.

### 57. What is production incident?

**Answer:** A live system issue affecting users or business.

### 58. What is RCA?

**Answer:** Root Cause Analysis finds why an issuehappened and how to prevent it.

### 59. What is postmortem?

**Answer:** A blameless review after an incident to learn and improve.

### 60. What is change management?

**Answer:** A controlled process for making production changes safely.

### 61. What is release management?

**Answer:** Planning, scheduling, testing, and deploying software releases.

### 62. What is feature flag?

**Answer:** A switch to enable/disable a feature without redeploying code.

### 63. Why use feature flags?

**Answer:** They support safe rollout, testing, rollback,and targeted releases.

### 64. What is MVP?

**Answer:** Minimum Viable Product: the smallest useful version to validate an idea.

### 65. What is stakeholder?

**Answer:** Anyone affected by or interested in the project outcome.

### 66. What is requirement ambiguity?

**Answer:** A requirement is unclear or can be interpreted in multiple ways.

### 67. How handle unclear requirements?

**Answer:** Ask examples, define acceptance criteria, document assumptions, and confirm withstakeholders.

### 68. What is estimation risk?

**Answer:** The chance that work takes more effort than expected.

### 69. How improve estimates?

**Answer:** Break tasks smaller, use historical data, include uncertainty, and review dependencies.

### 70. What is dependency?

**Answer:** A task, team, system, or decision neededbefore work can proceed.

### 71. What is blocker?

**Answer:** Something preventing progress.

### 72. How communicate blockers?

**Answer:** Raise early, explain impact, suggest options, and ask for needed support.

### 73. What is Agile ceremony?

**Answer:** A regular Agile meeting like planning, standup, review, or retrospective.

### 74. What is Agile artifact?

**Answer:** A useful work item like backlog, sprintbacklog, or increment.

### 75. What is increment?

**Answer:** The completed, usable product work delivered in a sprint.

### 76. What is capacity planning?

**Answer:** Planning sprint work based on teamavailability and expected effort.

### 77. What is spike?

**Answer:** A time-boxed research task to reduce uncertainty.

### 78. What is epic?

**Answer:** A large body of work broken into smaller user stories.

### 79. What is task?

**Answer:** A smaller technical step needed tocomplete a story.

### 80. What is roadmap?

**Answer:** A high-level plan of product direction and major milestones.

### 81. What is Agile mindset?

**Answer:** Focus on collaboration, feedback,adaptability, and delivering value.

### 82. What is continuous improvement?

**Answer:** Regularly making small changes to improve quality, speed, and teamwork.

### 83. What is stakeholder demo?

**Answer:** Showing working software to get feedback and alignment.

### 84. What is documentation in Agile?

**Answer:** Enough useful documentation to supportdevelopment, users, and maintenance.

### 85. Does Agile mean no documentation?

**Answer:** No. Agile means valuable documentation, not unnecessary heavy documentation.

### 86. What is API contract?

**Answer:** A clear agreement on request/responsestructure between systems.

### 87. Why API contracts matter?

**Answer:** They allow teams to build independently without breaking integrations.

### 88. What is architecture review?

**Answer:** A review of design choices for scalability,security, reliability, and maintainability.

### 89. What is non-functional requirement?

**Answer:** A quality requirement like performance, security, scalability, reliability, or usability.

### 90. What is performance requirement?

**Answer:** Expected speed, latency, throughput, or resource usage.

### 91. What is security requirement?

**Answer:** Rules to protect data, access, and systemsfrom threats.

### 92. What is maintainability?

**Answer:** How easy it is to understand, change, test, and fix software.

### 93. What is scalability?

**Answer:** The system's ability to handle more users, data, or requests.

### 94. What is reliability?

**Answer:** The system works correctly and consistently over time.

### 95. How would you work in an Agile AI project?

**Answer:** I would create clear user stories, build small prototypes, evaluate outputs, collect feedback, and improve each sprint.

### 96. How explain Agile in interview?

**Answer:** Agile is building software in small cycles,showing progress often, accepting feedback, and improving continuously.

### 97. What is the most important Agile habit?

**Answer:** Clear communication, because it prevents confusion, delays, and wrongassumptions.
