# Performance Review & Feedback


## Overview

A performance review is a conversation where a manager and employee discuss work results, strengths, improvement areas, and next goals.


## Why It Matters

Good reviews improve performance and trust. Poor reviews create stress, confusion, and resignations.


## Key Principles

- Give feedback regularly, not only annually
- Focus on behavior and results, not personality
- Balance strengths and improvement points
- Agree on action steps and support needed

## Key Terms

| Term | Definition |
|------|------------|
| **Feedback** | Information to help someone improve |
| **Appraisal Meeting** | Formal performance discussion |
| **Development Plan** | Steps to improve skills/performance |
| **Coaching** | Ongoing guidance for improvement |


## Use Case

Conducting quarterly reviews for team leaders in a logistics company.


## Scenario

> An employee is shocked by a low rating because no one gave feedback earlier. HR introduces monthly check-ins so issues are addressed early.


## Examples

- “Your reports are accurate, but submit them by Friday consistently.”
- “Great teamwork—next step is improving presentation skills for client meetings.”

## 3. Frameworks & Matrices

### Review Feedback Loop
**Purpose:** Turn performance from a once-a-year event into a repeating improvement cycle.

**Text Diagram:**
```text
observe work -> give feedback -> agree actions -> support -> review progress -> repeat
```
Axes / Quadrants / Components explained:
Observation: what actually happened in the work.
Feedback: the specific behavior or result to address.
Action agreement: the next step the employee will take.
Support: coaching, training, or resources needed to improve.
IT/AI/Product/Consulting worked example: A product manager misses sprint handoff deadlines, so the manager gives immediate feedback, adds a weekly checkpoint, and agrees on a delivery checklist [verified from model knowledge, not source]. The decision is to correct behavior before the next release slips.
When to pull this out in a meeting: When a manager says, "I should have said something earlier."

### Feedback Quality Matrix
**Purpose:** Separate useful feedback from feedback that creates defensiveness.

**Text Diagram:**
```text
                    Specificity
                 Low                 High
Tone   +----------------+----------------------+
Poor   | Vague criticism | Harsh but usable    |
Good   | Pleasant but    | Clear and actionable|
       | non-actionable  |                     |
       +----------------+----------------------+
```
Axes / Quadrants / Components explained:
Specificity: whether the feedback names a real behavior or result.
Tone: whether the message is respectful and fair.
Actionability: whether the employee can do something concrete with it.
Evidence: whether the feedback is based on examples rather than impressions.
IT/AI/Product/Consulting worked example: A consultant hears "be more strategic" versus "your recommendation should lead with business impact, not feature detail" [verified from model knowledge, not source]. The second version is more actionable because it tells the person what to change.
When to pull this out in a meeting: When feedback is vague, emotional, or stuck at the personality level.

### Coaching vs Appraisal Split
**Purpose:** Decide whether a conversation is for growth or for evaluation.

**Text Diagram:**
```text
coaching -> improvement
appraisal -> judgment / rating
both -> confusing if mixed badly
```
Axes / Quadrants / Components explained:
Coaching intent: helping the person improve.
Appraisal intent: deciding performance level or reward impact.
Psychological safety: whether the employee can learn without fear.
Documentation need: whether the conversation must support compensation or HR action.
IT/AI/Product/Consulting worked example: A team lead separates a Tuesday coaching session from the formal quarter-end rating discussion, so the employee can ask questions without worrying about the score being rewritten live [verified from model knowledge, not source]. The decision is to improve behavior in coaching and reserve appraisal for rating decisions.
When to pull this out in a meeting: When managers blur development conversations with compensation judgments.

### Development Plan Ladder
**Purpose:** Convert a review into a concrete improvement path.

**Text Diagram:**
```text
gap identified -> skill action -> practice -> check-in -> evidence -> close gap
```
Axes / Quadrants / Components explained:
Gap definition: what is missing, specifically.
Skill action: training, shadowing, reading, or practice.
Support: manager, coach, or peer help.
Evidence: the observable result that proves improvement.
IT/AI/Product/Consulting worked example: An analyst needs stronger client presentation skills, so the plan includes a slide clinic, one rehearsal before each meeting, and manager feedback after each presentation [verified from model knowledge, not source]. The decision is to make improvement measurable instead of aspirational.
When to pull this out in a meeting: When a review ends with "let's work on it" but no next step.

## 4. Formulas

The source is conceptual, so the formulas below are standard management tools expanded from model knowledge, not source text. [verified from model knowledge, not source]

### Formula 1: Performance Gap
Formula: `performance gap = target - actual`
Variables:
`target` = expected result
`actual` = realized result
Why this formula exists: It answers how far the employee is from the goal.
How to interpret the output:
Value near 0 -> on track -> reinforce and continue
Value moderately positive -> shortfall -> coach and support
Value large positive -> serious gap -> formal improvement plan
Worked example with numbers: If a support manager targets 95% service level and actual service is 88%, the gap is 7 points. Decision: if the shortfall is persistent, add support or escalate. [verified from model knowledge, not source]

### Formula 2: Goal Attainment Rate
Formula: `goal attainment rate = achieved goals / total goals`
Variables:
`achieved goals` = goals completed satisfactorily
`total goals` = all goals set for the period
Why this formula exists: It answers how much of the agreed work was delivered.
How to interpret the output:
Low rate -> weak execution -> review scope and blockers
Moderate rate -> mixed -> separate skill gap from resource gap
High rate -> strong -> consider stretch goals or promotion readiness
Worked example with numbers: If 8 out of 10 goals are achieved, the rate is 80%. Decision: keep the person in the role if the misses were minor; otherwise review the reason for the gap. [verified from model knowledge, not source]

### Formula 3: Development Completion Rate
Formula: `development completion rate = completed actions / planned actions`
Variables:
`completed actions` = training, coaching, or practice items finished
`planned actions` = total items in the plan
Why this formula exists: It answers whether the development plan is actually being executed.
How to interpret the output:
Low rate -> plan is not happening -> simplify or add accountability
Moderate rate -> progress exists -> keep the schedule
High rate -> plan is being executed -> review outcome change
Worked example with numbers: If 4 of 5 plan items are done, the completion rate is 80%. Decision: keep the plan but update the target behavior at the next check-in. [verified from model knowledge, not source]

## 5. Do vs Don't
| ❌ Don't | ✅ Do |
|---------|-------|
| Save feedback for the annual review. | Give feedback regularly so issues do not compound. |
| Attack personality instead of behavior. | Describe the specific behavior, result, or example. |
| Mix coaching and rating in one confusing conversation. | Separate growth discussions from formal appraisal decisions. |
| Leave a review without next steps. | End with a development plan, support, and due dates. |
| Let one manager's standards drift from another's. | Calibrate ratings so the process is fair across teams. |

## 6. Real-Life Scenarios (Metric-Driven)

### Scenario 1: Logistics quarterly review
Situation: A logistics team leader is getting quarterly reviews, and the manager wants to improve service without creating fear. The team has been missing handoff times even though results are otherwise strong. [verified from model knowledge, not source]
Applicable framework/metric: Review Feedback Loop + performance gap.
Analysis: If the target handoff time is 24 hours and actual is 30 hours, the gap is 6 hours. The manager can use that gap to set a specific action, like a checklist or a midpoint checkpoint.
Decision rule: If the gap is small, coach. If it is persistent, document a development plan. If the gap is large and recurring, escalate.
Action: Add a weekly review, assign a time-bound fix, and measure the next quarter's handoff time.

### Scenario 2: Shock low rating
Situation: An employee gets a poor rating and says no one gave feedback earlier. HR wants to stop surprises and keep trust high. [verified from model knowledge, not source]
Applicable framework/metric: Feedback Quality Matrix + review cadence.
Analysis: A yearly-only system creates long feedback lag. Moving to monthly check-ins gives the manager twelve opportunities to correct behavior rather than one.
Decision rule: If the review process creates surprise, increase cadence. If the feedback is already regular, improve specificity. If the rating standards vary, calibrate.
Action: Introduce monthly one-on-ones, require one behavior example in each, and document action items.

### Scenario 3: Product team presentation skills
Situation: A product analyst delivers good numbers but struggles to explain them to executives. The manager wants better presentation performance without demotivating the analyst. [verified from model knowledge, not source]
Applicable framework/metric: Coaching vs Appraisal Split + development completion rate.
Analysis: The development plan includes slide rehearsal, a mock exec review, and feedback after each meeting. If all three actions are completed, the completion rate is 100%; if only one of three is done, the plan is not being executed.
Decision rule: If skill is coachable, use development. If a formal standard is repeatedly missed, use appraisal. If progress stalls, escalate.
Action: Put presentation coaching into the calendar and review the next two presentations for evidence of improvement.

## 7. Implementation Playbook

1. Set a regular feedback cadence instead of waiting for annual cycles.
2. Define performance goals in observable, measurable terms.
3. Use behavior-based feedback with specific examples.
4. Separate coaching conversations from rating conversations when possible.
5. Write a development plan with actions, owners, and deadlines after each review.
6. Calibrate ratings across managers to reduce bias and inconsistency.
7. Track goal attainment and development completion so the review system stays real.
