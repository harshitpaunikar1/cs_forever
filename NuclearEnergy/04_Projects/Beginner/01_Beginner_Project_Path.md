# Beginner Project Path

## Overview

Beginner projects should build confidence with calculations, plotting, simple instrumentation ideas, and technical writing.

## Recommended Projects

1. Reactor heat-generation calculator
1. Steam-cycle efficiency calculator
1. Radiation inverse-square and shielding calculator
1. Alarm-log parser in Python

## Project Standard

Each project should include:

- assumptions
- input and output examples
- plots or screenshots
- one-page explanation of what the result means physically

## Skills Reinforced

- Python
- plotting
- unit handling
- technical communication

## Common Pitfalls

- too little explanation
- no validation cases
- projects that are only formulas with no interpretation

## 🔧 Industry Enrichment (Appended)
---

### Real-World Implementation

Beginner nuclear projects should look like the first week of useful engineering support, not like a research thesis. The right scale is calculators, system diagrams, clean plots, tagged signals, and short technical notes that show you can reason about plant-shaped inputs without pretending you already run a station.

### Industry Tool Stack

- `Python`, notebooks, and plotting
- markdown notes and diagrams
- simple CSV or synthetic historian-like data
- unit handling and engineering checks

### Step-by-Step Applied Workflow

1. Pick one small plant question such as heat balance, decay heat trend, or sensor conversion.
2. Build the calculation or plot.
3. Add units, assumptions, and a short note on what the result means physically.
4. Show one validation check or sanity check.

### AI Integration

At this level, AI is best used for drafting code structure or plot ideas. The learner still needs to verify units, equations, and plant meaning manually.

### Case Studies

- `MIT OCW` style engineering exercises are a good benchmark for beginner rigor.
- `OpenMC` examples are a later benchmark, not the starting point for most learners.

### Failure Modes & Safety

- turning a simple calculator into a vague "AI platform"
- no units or validation
- copied formulas with no interpretation

### Business & Commercial Layer

These projects do not sell directly, but they prove entry-level readiness for plant-support, controls, analytics, and simulation roles.

### Hiring Signal

One clean beginner repo with explanations beats five noisy mini-projects with no validation.

### Portfolio Projects

- Beginner: keep the existing project list and add `README.md`, `assumptions.md`, and `validation.md` to every repo.
- Intermediate bridge: add one synthetic trend or alarm context around the calculation.
- Advanced bridge: connect the calculator to a plant decision note.

### Future Trends (2026 / 2030 / 2035 / 2045)

- `2026`: clean engineering basics still differentiate software-heavy candidates.
- `2030+`: the projects that age well are the ones with explicit assumptions and reproducibility.

### Interview Questions

1. What should a beginner nuclear project prove?
   Short answer: basic systems thinking, units discipline, and technical communication.
2. Why is validation important this early?
   Short answer: because trust starts with simple checks.
3. What is the main beginner mistake?
   Short answer: output without physical interpretation.
4. Where can AI help safely?
   Short answer: code scaffolding, not result authority.
5. What repo files are mandatory?
   Short answer: README, assumptions, validation, and reproducible run steps.
