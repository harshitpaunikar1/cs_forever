# Foundation

## Overview

The Foundation section exists to make the rest of the curriculum possible. It teaches the habits and mental models that prevent later confusion: how programs are structured, how to use the terminal and Git, how memory behaves, why languages feel different, and how software actually reaches hardware.

A common mistake in self-study is jumping straight into frameworks. That produces surface familiarity without depth. This section deliberately starts lower. By the end of Foundation, you should be able to work comfortably in a terminal, read simple code in multiple languages, debug beginner-level mistakes, and explain what your machine is doing when it runs a program.

## What This Section Covers

### 1. Start Here
- A map of the curriculum and the order in which to study it.
- The role of mathematics, programming languages, and systems thinking.
- A realistic expectation for how to study independently.

### 2. Programming Basics
- Computational thinking and problem decomposition.
- Control flow, variables, functions, and debugging.
- Git, shell usage, files, processes, and basic Linux workflow.

### 3. C Programming
- Compilation, linking, memory layout, pointers, arrays, structs, and undefined behavior.
- Why C remains the language that clarifies how systems software works.

### 4. Python Fundamentals
- Productive high-level programming.
- Core syntax, functions, modules, built-in data structures, and classes.

### 5. Rust Fundamentals
- Ownership, borrowing, type-driven design, and modern systems programming.
- Cargo, tests, enums, pattern matching, and error handling.

### 6. Computer Basics
- CPU, memory, storage, operating system, compiler, and runtime interactions.
- A concrete model of how software moves through the machine.

## Milestones

You are ready to leave Foundation when you can do all of the following without heavy hand-holding:

- Write, run, and debug small programs in C, Python, and Rust.
- Use Git for regular commits, branching, rebasing, and reviewing diffs.
- Explain stack vs heap, pointers vs references, and compiled vs interpreted execution.
- Read simple shell pipelines and use them to inspect files and logs.
- Describe how source code becomes a running process.

## Time Guidance

A realistic range is `6-10 weeks` at `8-12 hours per week`, or faster if you already code regularly. The goal is not speed. The goal is durable understanding.
