# Curriculum Overview

## Overview

Computer science is the study of computation and the systems that make computation useful, reliable, and efficient. Programming is one tool inside that field, but it is not the whole field. A strong curriculum teaches you how to reason about algorithms, memory, concurrency, storage, communication, and system behavior under failure.

This guide is structured to feel like a serious self-directed program rather than a list of disconnected links. Each layer prepares you for the next one: languages and workflow first, then core systems, then advanced infrastructure and research-oriented topics, and finally projects that prove you can apply the material.

## Why This Curriculum Is Structured This Way

### Foundations come before specialization
Without shell fluency, version control discipline, and low-level memory intuition, later topics such as operating systems, databases, and distributed systems feel abstract or confusing.

### Core CS creates transferability
Algorithms, architecture, operating systems, databases, and networking are the subjects that continue to matter when languages, frameworks, and deployment trends change.

### Advanced topics only make sense after the core
Containers, Kubernetes, consensus, security testing, GPU operations, and media pipelines all depend on lower-level ideas. Studying them too early produces memorization instead of understanding.

## Curriculum Layers

### Foundation
Build programming fluency, developer workflow, language fundamentals, and a machine-level model of execution.

### Core CS
Study the classic systems backbone: data structures, architecture, operating systems, databases, networking, and backend services.

### Advanced
Go deeper into distributed systems, security, cloud-native tooling, observability, AI infrastructure, kernel internals, and media systems.

### Projects
Turn theory into evidence. Each project path is meant to create reusable artifacts, not throwaway exercises.

## What You Should Be Able To Do By The End

- Read and write code across low-level and high-level languages.
- Explain time and space tradeoffs, memory behavior, and process boundaries.
- Build small services and reason about storage, networking, and failure modes.
- Navigate official documentation instead of depending entirely on tutorials.
- Choose the right abstraction level for the problem in front of you.

## Study Principles

### Learn actively
Read less, type more. Recreate examples, make mistakes, and explain concepts in your own words.

### Keep notes short and operational
Do not copy whole documents. Keep summaries, commands, diagrams, and edge cases you had to debug.

### Prefer primary sources
Official manuals, specifications, and project documentation are more durable than most secondary tutorials.

### Revisit topics after more context
The second or third pass through operating systems or networking is where real understanding usually appears.

## Common Pitfalls

- Collecting languages instead of learning one model deeply.
- Consuming videos passively without building anything.
- Avoiding C, operating systems, or networking because they feel harder.
- Treating official docs as reference-only rather than a learning tool.
