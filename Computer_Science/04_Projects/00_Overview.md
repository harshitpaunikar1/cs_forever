# Projects

## Overview

Projects are where this curriculum stops being theoretical. A project proves that you can make design choices, structure code, debug problems, document decisions, and finish something coherent enough for another engineer to inspect.

The project paths are split by difficulty so you can choose a starting point that is ambitious without being unrealistic.

## How To Use the Project Paths

### Beginner
Choose this if you are still building confidence with language basics, file handling, testing, and CLI workflows.

### Intermediate
Choose this if you can already complete small standalone programs and want to build networked or systems-oriented applications.

### Advanced
Choose this if you are comfortable with concurrency, storage, deployment, performance work, or distributed systems.

## Quality Bar for Every Project

Every project should include:
- a short design note or README
- setup and run instructions
- tests or clear manual verification steps
- version control history with meaningful commits
- at least one section describing limitations and next improvements

## How To Choose Well

Pick projects that reinforce the parts of the curriculum you want to retain. A smaller project completed cleanly is more valuable than an ambitious one abandoned halfway through.
